MemoryGarden

Where Memories Bloom — a storybook that opens into your own garden. You write a memory in a botanical journal, choose a flower, plant it, and watch it grow in place. Tapping the flower later reopens the page. Everything is kept in this browser.

A snapshot of the code after commit 4e874a2 plus the intro-video and wrap-up changes committed with this map. It can drift as the code changes.

The main pieces

Storybook shell

src/app/App.tsx runs the phases: closed book → intro (Flow clip on wide screens, CSS opening on phones) → garden → closing.

Painted garden

src/art/GardenWorld.tsx layers the painted plate, soil beds, leaves and small atmosphere. src/components/garden/GardenScene.tsx puts flowers and tap targets on the 14 spots.

Journal

src/journal/Journal.tsx (write, preview, read, edit, delete) and src/journal/PageLayout.tsx (the one adaptive page).

Browser storage

src/lib/db.ts keeps memories and one draft in IndexedDB. No accounts, servers or cloud copies.

One action, end to end: planting a memory

A reference route through the code

A reference route for exploring later; it was not toured interactively. Search for the anchor text in each file.

  1. src/app/App.tsx — startMemory and plantMemory

    startMemory picks the tapped spot (or the first free one, moving to a new garden page when 14 are full) and opens the journal, restoring an unfinished draft if there is one. plantMemory saves the memory, then starts the growth with plant().

  2. src/journal/Journal.tsx — async function plant()

    Checks the title and story, blocks double clicks with busy, and keeps the journal open with the writing intact if saving fails. A nearby effect autosaves drafts with store.saveDraft.

  3. src/lib/db.ts → src/art/flowers/FlowerArt.tsx

    store.plant(memory) writes the memory and clears its draft in one transaction. In the garden, GardenScene passes the growing stage to FlowerArt, which marks each painted stage image current, past or future (data-state={state}) so it grows up from the soil.

A practice to reuse

Normalise generated art against a measured anchor instead of trusting it. The sunflower growth stages came from one generated sheet, yet their stem bases drifted between 448 and 513 px, so the plant would have jumped sideways while growing. Later flower sheets arrived as JPEGs with a painted checkerboard instead of transparency.

Evidence: scripts/prepare-assets.mjs measures each stage's stem base (stemBase) and shifts every frame to one soil point, and checkerSheet removes painted checkerboards; the checklist's Revisions record both findings.

On another project: whenever AI-generated or third-party assets must line up, decide the alignment rule up front, measure it with a script, and fix the assets in a repeatable step rather than by hand.
