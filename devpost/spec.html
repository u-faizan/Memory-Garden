Follow one memory

From protected draft to lasting bloom.

1 · Enter and write App, journal, and draft controller

Load the illustrated scene, open IndexedDB, and restore saved pages/memories. Offer any draft with Continue Writing / Not Now. Journal input updates memory immediately and queues a serialized 500 ms local save; photos are processed locally.

Files: src/app/App.tsx, src/journal/MemoryEditor.tsx, src/hooks/useDraft.ts. PRD: The Core Journey; Protect One Active Draft.

2 · Discover or choose manually Optional external AI, explicit consent

Manual selection sends nothing for AI. Find My Flower explains external processing and obtains a fresh bot token after explicit action. Only current text goes through the Function. Suggestions are validated and editable; never rewrite the story or restrict flower choice by emotion.

Files: src/lib/ai.ts, functions/api/suggest-flower.ts, shared/contracts.ts. PRD: Discover and Review a Flower.

3 · Review and choose a spot Simple, protected placement

Suggest an empty spot automatically. Proposed layout: Choose another spot temporarily reveals the garden with an understated Confirm / Back strip and highlighted empty targets. Preserve all draft fields; occupied spots cannot be overwritten. Ten stable logical IDs map to desktop/mobile coordinates.

Files: src/garden/scene.ts, src/storage/placement.ts. PRD: Planting Spots and Garden Pages.

4 · Save, then bloom One local transaction before celebration

Flush the draft and commit memory insertion, placement/page update, and matching-draft removal together. Only then close the journal and show seed → sprout → young plant → chosen bloom. Stable IDs, a unique placement index, and operation locking prevent duplicate planting. Failure retains the draft and shows retry.

Files: src/storage/repository.ts, src/garden/Bloom.tsx. PRD: Plant and Bloom. Reload restores the final saved flower even if animation was interrupted.

5 · Read, return, or delete The same intimate journal

Open original text/date/title/theme/flower/photo without AI. Desktop is a two-page botanical book; mobile is a comfortable scrollable page. Back to Garden / Escape restore the same page context and focus.

Let this memory go?

This will remove the memory and its flower from your garden. This action cannot be undone.

Keep My Memory is primary; Delete Forever explicitly confirms. Transactional success frees the original spot, preserves other flowers, removes only empty trailing pages, then peacefully fades/removes the flower. A failed deletion never appears successful.

Files: src/journal/MemoryReader.tsx, src/components/ConfirmDialog.tsx, src/storage/repository.ts. PRD: Revisit, Persist, and Delete; Delete With Confirmation.

Four local stores

Simple records. Reliable transactions.

StoreContents / lifetime
memoriesOriginal story, title, theme, flower enum, date, created timestamp, page/spot, optional photo blob, stable variation seed. Created once, read, explicitly deleted. Unique placement index.
draftsOne active draft ID/revision, fields/selections/photo and updated timestamp. Draft ID becomes memory ID on successful planting.
pagesStable ID/order. Reuse one scene; no renumbering or moving populated flowers. Preserve internal gaps; remove only empty trailing records.
preferencesLocal consent acknowledgment/version and last viewed page. An acknowledgment never automatically triggers analysis.

Photos live in their owning record; no remote media system. Planting inserts memory, updates page allocation, and removes the matching draft in one transaction. Failure rolls everything back. Automatic placement prefers the current page, then existing free space, then a new page.

Honest draft protection: flush on controlled exits and show “Draft saved” only after success. A forced crash/reload can lose the last unsaved debounce-window keystrokes; storage clearing or unavailability cannot be made loss-proof by IndexedDB.

Optional and bounded

One request. Three editable suggestions.

API contract

POST /api/suggest-flower, same-origin JSON, bounded at 12 KiB while reading. Request contains only memoryText, consentVersion, and fresh turnstileToken.

Response contains only title (1–100), emotionalTheme (1–120), and flowerType (one of six IDs). Strict schema, required keys, no extras; validate on server and browser. Errors are friendly JSON without upstream content or memory echoes.

Initial OpenAI integration

Responses API with gpt-6-luna for initial testing, configurable only through server-side OPENAI_MODEL; reasoning none, at most 320 output tokens, store:false, no tools, no automatic retry. Handle refusal, incomplete output, invalid fields, quota and timeout safely.

Official standard text prices checked: $0.10/million input and $0.50/million output tokens, with separate cache charges. Availability and quality for the learner's account still require one fictional live call. Model documentation.

Public endpoint safeguards Risk reduction, not an abuse-proof promise

Fresh server-verified Turnstile token with expected hostname/action; bounded input/output/timeouts; exact Origin checks; one browser request at a time; proposed 20 s browser cooldown and transient per-isolate burst checks; AI disable switch. No story/raw-IP persistence or application content logs. Manual mode remains available.

Pages does not document the Workers Rate Limiting binding as supported. Do not assume a zone WAF rule is available for a free pages.dev hostname. Enable stronger rate controls only if supported and tested on the actual project; do not silently add another storage service/Worker.

Project alerts notify; they do not stop requests. A suggested $1 demo alert requires learner approval. No hard global spend cap or durable visitor quota is claimed. Solved challenges/distributed clients can still incur cost; public AI stays off until configuration and residual-risk review.

Provider retention and the bot-check service are explained before AI use. No photos are uploaded. Check OpenAI data controls, Pages bindings, and spend-alert semantics.
